# 文序产品目标与需求定位

基线日期：2026-09-21；更新日期：2026-09-27。状态：v0.6 编辑基线加教案模板校准增量设计。桌面受控模板流程已接通，具体见[模板验证记录](verification/template-workflow.md)；当前编辑能力与验收边界见 [实施记录](verification/v06.md) 和 [桌面版记录](verification/windows-desktop.md)。本文面向产品、研发与验收人员。

## 1. 为用户完成什么

文序帮助用户调整已经写好的 Word 文档。用户可以点击按钮统一正文格式，也可以选中一处文字或描述某个栏目，只修改需要的格式，获得可继续编辑的 Word 文件。

当前先聚焦教案中的反复格式修改，不扩展为通用论文排版或教学内容生成工具。教案可能同时存在普通段落、表格填写区、图片、公式与批注，用户希望精准修改并保留原稿的其余部分。

领导给出的模板可能旁批要求正确，实际格式却不符合要求。产品必须先以旁批为依据校验并修正这份模板文件，保存后重新核验，通过后确立为金标准，后续教案的 v1、v2 修改再采用这个修正后的基准。只展示差异或生成规则清单不算完成。详见 [教案模板校准与金标准版本设计](specs/lesson-template-calibration.md)。

如果模板没有旁批，直接自动识别正文、各级标题等类别并提取现有有效样式，以原模板作为后续依据。明确结果无需再校准文件或逐项人工确认；仅在分类或同类格式存在歧义时提示核对。

产品价值由三个结果决定：范围找得准、要求改得对、其他部分保得住。自然语言和模板用于减少操作成本，常用格式调整必须能直接通过前端控件完成。

preview.2使用反馈后的新方向为“预览优先、少操作”：主界面直接按当前金标准整理，不要求用户理解或选择一长串自动识别的栏目；规则按教案业务区域组织，设置与识别详情按需打开。金标准可在保持同一模板内容及表格结构的前提下反复调整，最新设置落实到实际模板并预览验证。此轮界面调整仍为设计，尚未改代码。

## 2. 模板准备与编辑路径

导入模板时自动分流：有旁批，读取旁批与位置 → 确定角色、格式及作用范围 → 修正模板文件 → 重新打开复核 → 确立金标准；无旁批，自动识别分类 → 提取现有有效样式 → 形成基准，原文件无需修改。旁批读取失败或无法理解不能误报为“无旁批”。未解决的分类/格式歧义、适用要求漏检查或保全失败不能冒充已明确的基准。

日常主路径为“打开教案 → 按金标准整理 → 查看修改后预览 → 保存”。“调整金标准”是次级入口：只改区域格式，保留教案内容，应用后看效果，可以继续微调。模板修订和教案v1/v2由系统分别记录，主界面不同时展开多套版本清单；以下全局/局部能力作为标准设置或临时局部修改的按需操作。

| 路径 | 用户表达 | 应有结果 |
| --- | --- | --- |
| 全局调整 | 正文统一宋体小四，其他控件保持原样 | 只调整被确认属于正文的对象及指定属性，范围和排除项可见 |
| 局部调整 | 将“教学目标”栏的填写内容改为黑体五号 | 找到具体填写区，保留栏目标签、相邻单元格和其他格式 |
| 组合调整 | 正文宋体小四，但第三段字体为黑体 | 第三段黑体小四，其余正文宋体小四；按属性合并 |
| 继续调整 | 在上次结果上只改行距 | 保留已经得到的字体、字号和局部结果，另存新版本 |

全局表示“指定类别或范围内统一调整”。核对范围时仍可展开正文、各级标题等具体内容、位置和依据，但这些信息不再常驻日常主界面。当前教案按表格行列标题、教学内容、师生活动/设计意图、课堂小结/作业布置/板书设计内容四组组织标准；具体字号与例外见[区域格式规则](specs/lesson-template-calibration.md)。

## 3. 必须守住的编辑语义

1. **未指定就保持。** 不自动改文字、不润色、不补齐其他格式。控件当前值与本次目标值分开；混合格式不套默认值；加粗等控件支持保持、开启、关闭。
2. **全局和局部共用一套计划。** 同批次的明确局部例外按属性覆盖对应全局设置；同一目标属性仍有歧义时显示冲突，不随机选值。
3. **每次修改基于明确版本。** 旧局部结果不会因新一轮无关属性调整而丢失；用户后续明确全局修改同一属性时，可以覆盖历史局部结果，显式保护或排除的区域除外。
4. **定位和影响范围可见。** 重复文本需要消歧；只选几个字却设置段落行距时，显示其作用于整个段落。页码只用于预览导航，修改绑定版本与文档对象。
5. **保存原稿，输出新版本。** 支持预览、撤销、继续修改；失败不覆盖原稿或已有版本，未完成项不掩盖在总体成功提示里。
6. **检查结果真实。** 目标属性、未指定部分和对象保全独立校验；渲染完成与人工版式复核分开记录。

修改字号、字体或行距可能自然引起重新换行和分页。工具应展示这些变化，不能为了保持页数而擅自缩字、删内容或修改其他属性。

## 4. 本阶段范围

| 范围 | 定位 |
| --- | --- |
| P0：全局与局部格式闭环 | 全局控件、搜索和局部选择、文字要求统一解析、修改清单、明确冲突、精准执行、预览、导出、撤销与继续修改 |
| P0：真实场景必要基础 | DOC 原格式副本与独立核对；表格栏目定位；批注、公式、图片、合并关系等对象的保全验证；未指定属性保持 |
| P0：教案模板增量设计 | 有旁批的定位、规则解释、模板实际修正与复核；无旁批的自动分类与样式提取；共用分类内容展示、金标准确立、后续教案版本绑定；桌面支持子集已接通，未支持项明确保留 |
| P1：扩展格式与重复使用 | 个人格式预设、基础模板校准之外的复杂语义扩展、编号整理、表格布局与分页属性、页眉页脚格式等，逐项定义和验收 |
| 后续独立评估 | 多文件批量处理、组织规范发布和跨会话持久化等；不作为当前 P0 前提 |
| 当前范围之外 | 正文生成或润色、业务内容审核、教学质量判断、课程名称或必填内容检查、复杂文档合并 |

不自动执行非格式业务审核，不等于忽略包含这些要求的旁批。校准清单必须保留并标出需外部资料、课后处理或人工检查的事项及适用阶段，不把它们算作格式检查通过。模板允许的填写空位与正式教案必填项分开；类型或适用范围尚不清楚时仍需核对。

v0.6 已加入 DOC 原格式编辑和经过验证的复杂对象保全子集，原格式核对和客户端兼容性仍按独立状态检查。某类对象的“可读取”“可原样保留”“可修改”必须分开声明；文件无法可靠读取、关系无法保全或请求超出支持能力时，阻止对应操作并说明原因。

## 5. 与现有 v0.5 的关系

v0.6 保留“用户自己的稿件、只改确认属性、保留原稿、检查后交付”的基础，补充两条更直接的操作路径和更精确的对象定位。

| 当前 v0.5 POC | v0.6 目标 |
| --- | --- |
| 文字要求或参考实例生成规则核对表 | 增加无需提示词的全局控件和局部选择入口，全部入口共用编辑协议 |
| 角色和段落层的格式规则 | 扩展到字符片段、表格栏目与单元格等实际对象 |
| 普通 DOCX 的受控结构；部分复杂对象预检拒绝 | 增加 DOC 原格式编辑与真实教案复杂对象保全，按验证通过的能力开放 |
| 按范围和属性组织规则 | 对实际重叠对象逐属性合并，形成冻结后的唯一执行计划 |
| 已有有限 XML 修改、校验、Linux 渲染 | 保留这些基础，补定位、复杂对象能力和独立的视觉复核状态 |
| 会话内版本记录 | 保留原稿/输入版本/计划/结果的来源关系；跨会话恢复另行实现 |

详细代码映射、模块契约和实施次序见 [架构设计](ARCHITECTURE.md)。这些逻辑层第一阶段放在同一个 Python 应用中，后续只有出现明确运行需求时再拆服务。

## 6. 如何判定真实场景可用

全局调整覆盖准确，局部调整定位准确，二者都只改变明确指定属性，并通过 [V06-A01 至 V06-A14](REQUIREMENTS.md) 中对应场景。教案模板与预览优先增量使用 [TPL-A01 至 TPL-A20](specs/lesson-template-calibration.md)；仅完成旁批读取、单次试修或样式提取不足以宣布完整流程可用。

Windows 桌面主线在 Windows 与实际 WPS 环境验证，原网页/WSL 路线按对应环境记录。真实文档要检查内容、格式、对象保全和前后页面；Word/WPS 实际打开与继续编辑属于客户端兼容性验收，不能用另一引擎渲染或合成文档结果替代。

交付必须区分已验证、待复核、未支持和失败。只有前端按钮、只有可导出文件，或只有架构图，都不足以证明本阶段目标完成。


### 2026-09-22 原格式保真契约

用户已选择保真优先，输出保留上传格式。DOC 不再强制转换为 DOCX；原格式工作副本在无修改时须与上传文件字节相同。DOC 的原生修改只接受冻结计划中的目标属性，重新打开保存结果并核对全文、范围外格式、批注关联、关系、媒体与 OLE 流；失败不登记版本。DOCX 保持现有最小补丁路线。架构图中的读取、建模、执行、校验与交付职责保持不变，精确修改引擎按原格式分派。
